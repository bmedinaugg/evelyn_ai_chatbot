# M1c Chat Widget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Visitors of the Freshdesk help portal (support.trainmore.com, nl/en) get a TrainMore-branded chat widget. It shows a consent notice, a chat with validated answers and source links, a contact hand-off, and a lead form with Turnstile, all backed by the M1b API.

**Architecture:** `apps/widget` (Vite + Preact) builds two things:
- **`loader.js`:** a tiny vanilla script for the portal's layout. It adds a launcher button and an iframe, and detects the language from the portal path (`/nl/…` or `/en/…`).
- **The iframe app** (`index.html`) on its own origin, which talks to the API.

All logic that can be pure is pure and unit-tested with Vitest (language detection, URL safety, API client, chat reducer). The UI is tested end-to-end with Playwright against `vite preview`, with the API and Turnstile mocked via `page.route`.

**Tech Stack:**
- Approved 2026-11-11: Preact 11.2.0, Vite 8.3.7, @preact/preset-vite 2.10.6, @playwright/test 1.65.0
- Existing: Vitest 5.1.0, `@trainmore/i18n`

**Spec:**

## Global Constraints
- **Inherited:** strict TS, exact pinned deps, all user-facing text nl+en via `@trainmore/i18n`, no personal data in logs or storage beyond what's needed.
- **Text rendering:** model and FAQ text is always rendered as text (Preact escaping), **never** via `dangerouslySetInnerHTML`. Links come only from API `citations[].url`/`contactUrl` and only if `https:`. They open with `target="_blank" rel="noopener noreferrer"`.
- **No third-party requests except Cloudflare Turnstile**, and only when the lead form is shown. No Google Fonts (they send visitor IPs to Google). The font stack is `Roboto, system-ui, sans-serif` and `Montserrat, …` for headlines when locally available.
- **CSP** (meta in the iframe `index.html`):
  - `default-src 'self'`
  - `script-src 'self' https://challenges.cloudflare.com`
  - `frame-src https://challenges.cloudflare.com`
  - `connect-src 'self' <API origin>`
  - `style-src 'self'`
  - `img-src 'self' data:`
  - **No inline styles**: CSS classes only.
- **Storage:** `sessionStorage` in the iframe origin only, for `{ conversationId, token, consentGiven }`. Never localStorage, never cookies.
- **Config via Vite env:** `VITE_API_BASE_URL`, `VITE_TURNSTILE_SITE_KEY` (local: `1x00000000000000000000AA`), `VITE_PRIVACY_URL`. The loader takes `data-widget-url` from its script tag.
- **Brand:** black background, white text, red `#fa194a` only for the launcher, send button, links/accents and focus rings. Bot bubbles are carbon grey `#2C2C2C`; user bubbles are white with black text. Headline uppercase (Montserrat 900 fallback). Body in sentence case.
- **CORS:** the API's `WIDGET_ALLOWED_ORIGINS` is the **iframe** origin (the widget host), not the portal. Update `.env.example` and ARCHITECTURE.
- **Commits:** on branch `m1c-widget` (stacked on `m1b-answering`), with the standard trailer.

## Review Focus
1. **HTML or script in a reply or citation title** (`<img onerror>`, `javascript:` URL) is shown as text, and the link is dropped. (Tasks 2 and 4)
2. **Expired or unknown conversation (404).** The widget silently starts a new conversation and resends once, rather than getting stuck. (Tasks 2 and 3)
3. **Double submit while waiting, and 409 busy.** The input is disabled while sending. A 409 shows the "still working" text, without a duplicate message bubble. (Tasks 3 and 4)
4. **No consent:** no API call is made before the visitor accepts. (Task 4)
5. **Portal language detection on odd paths** (`/en-us/…`, `/`, `/NL/`) falls back to `<html lang>`, then `nl`. (Task 2)

### Task 2: Widget core logic (`apps/widget/src/lib`, pure)
- **Produces:**
  - `detectPortalLang(pathname: string, htmlLang: string | null): Lang`
  - `safeHttpsUrl(url: unknown): string | null`
  - `createWidgetApi(opts: { baseUrl: string; fetch?: typeof fetch })` exposing `createConversation(lang)`, `sendMessage(session, text, pageLang)` and `submitLead(input)`
  - `type ApiReply = { text; lang; citations: {articleId,title,url}[]; action: 'none'|'lead_form'|'contact'; contactUrl? }`, zod-validated
  - `class WidgetApiError { kind: 'busy'|'rate_limited'|'not_found'|'verification_failed'|'invalid'|'network'|'server' }`
  - `chatReducer(state: ChatState, event: ChatEvent): ChatState`, covering consent, send start/success/error, the lead form open/submitted states, and new chat
- **Tests:** each function, including the Review Focus items 1, 2, 3 and 5 at the logic level.

### Task 3: Loader script (`apps/widget/src/loader.ts`)
- `mountLoader(doc: Document, opts: { widgetUrl: string; lang: Lang })`:
  - creates a red launcher button (`aria-label` = `widget.open`) and a hidden iframe (`title` = `widget.title`, `src` = `${widgetUrl}?lang=…`)
  - toggles on click
  - listens for `postMessage({ type: 'trainmore-widget:close' })` from the widget origin only
  - Esc closes
- **Bootstrap:** reads `document.currentScript.dataset.widgetUrl`. A missing or non-https URL (outside localhost) means it does nothing.
- **Pure helpers:** `buildIframeUrl`, `isWidgetMessage(event, widgetOrigin)`, unit-tested.
- **Styles:** injected via a CSS file built alongside (no inline style attributes).

### Task 4: Widget app UI (`apps/widget/src/app`)
- **Components:**
  - `App` (header with close button that posts the close message)
  - `ConsentNotice` (text, privacy link, accept)
  - `ChatView` (aria-live log, bubbles, typing indicator, sources list, contact link, input with a 1000-char limit, disabled while sending)
  - `LeadForm` (email, phone optional, question, consent checkbox, Turnstile container, submit/cancel)
  - `useTurnstile` (loads `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit` on demand, renders with the site key, returns the token)
- **Session** in sessionStorage. A 404 means: clear the session, create a new conversation, resend once.
- **Playwright e2e** (API and Turnstile mocked):
  - consent gate (no request before accepting)
  - question → answer with a source link
  - hand-off shows the contact link
  - an HTML reply shows as text
  - a `javascript:` citation renders no link
  - 409 shows the busy text with no duplicate bubble
  - 404 starts a new conversation and resends
  - lead form happy path (token from the stubbed Turnstile) and a failed verification
  - the language comes from `?lang=nl`
  - the loader on a test host page opens and closes the iframe

- README: run the widget locally against the API, and the env keys.
